# Bundled dependencies

ContainerScope ships everything it needs to run inside `ContainerScope.app/Contents/Resources`. This page explains what each component is, where it comes from, how it's pinned, and how to update it. Licences are listed in [THIRD_PARTY_NOTICES.md](../../THIRD_PARTY_NOTICES.md).

## What's in the bundle

| Folder | Component | Source | Modified? | Signed by |
|---|---|---|---|---|
| `Engine/` | Apple `container` 1.5.0: CLI, `container-apiserver`, plugins (including machines and Kubernetes) | Apple's signed installer package from [apple/container releases](https://github.com/apple/container/releases) | No. `bin/` and `libexec/` are copied out of the package; the installer's `uninstall-container.sh` and `update-container.sh` are left out | Apple (Developer ID) |
| `Kernel/` | Linux 6.18.35 `vmlinux` (Kata Containers 3.32.0 build, ~30 MB) | `kata-static-3.32.0-arm64.tar.zst` from [kata-containers releases](https://github.com/kata-containers/kata-containers/releases), the same kernel the engine recommends | No | (data file) |
| `QEMU/bin`, `QEMU/lib`, `QEMU/share/qemu` | `qemu-system-aarch64`, `qemu-img`, `swtpm` and their dylibs; option ROMs, VGA BIOSes and keymaps | Homebrew bottles (`brew install qemu swtpm`) | Library install names rewritten to `@rpath`; code unchanged | ContainerScope's Developer ID; `qemu-system-aarch64` has `com.apple.security.hypervisor` |
| `Firmware/` | Secure Boot UEFI: `AAVMF_CODE.ms.fd`, `AAVMF_VARS.ms.fd`, `VERSION` | Built from Ubuntu 24.04's `edk2` source package by [`Firmware/build-aavmf.sh`](../../Firmware/build-aavmf.sh) | Boot logo replaced; trailing zero padding trimmed | (sealed by the app signature) |
| `ThirdParty/` | Licence texts, `homebrew-formulae.txt`, `versions.json` | Generated by `Scripts/fetch-deps.sh` | — | — |

`Bundled.swift` is the only place in the app that knows these paths.

### Why each one is bundled

- **Engine.** Without it, users had to install `container` with Homebrew or Apple's installer (which needs an administrator password) before the app could do anything. The bundled copy runs in place with `--install-root`, so nothing is installed system-wide. A user-installed engine still takes priority (see [Architecture › Finding the engine](architecture.md#finding-the-engine)).
- **Kernel.** On first start the engine otherwise downloads the ~700 MB Kata release archive to extract one 30 MB file.
- **QEMU and swtpm.** Windows on ARM needs QEMU (Virtualization.framework can't run Windows) and a TPM 2.0 for Windows 11.
- **Firmware.** Windows 11 needs Secure Boot with Microsoft's keys enrolled. The EDK2 firmware that comes with Homebrew's QEMU has no keys enrolled, so we build Ubuntu's AAVMF, which ships with them pre-enrolled.

### Not bundled

Rosetta 2 (part of macOS), Windows 11 ISOs (Microsoft's licence; downloaded in the app from Microsoft), the VirtIO driver ISO (~880 MB, downloaded in the app from Fedora), container images, and socktainer (optional, `brew install socktainer`). The **Requirements** section of the Engine page (`CS.requirements` in `core.js`) lists these as **You provide** / **Optional** next to the **Included** bundled components; Overview shows a banner only for items tagged **Needs attention**.

## Pinning

[`Scripts/deps.env`](../../Scripts/deps.env) pins what's downloaded:

| Variable | Meaning |
|---|---|
| `CONTAINER_VERSION`, `CONTAINER_PKG_URL`, `CONTAINER_PKG_SHA256` | Apple's signed engine installer |
| `KATA_VERSION`, `KATA_URL`, `KATA_SHA256` | Kata Containers static release archive |
| `KERNEL_MEMBER`, `KERNEL_VERSION` | Path of the kernel inside that archive, and its version |
| `QEMU_FORMULAE` | Homebrew formulae copied into `QEMU/` |

Downloads are cached in `~/Library/Caches/ContainerScope-build` (or `$DEPS_CACHE`) and verified against the SHA-256 on every run; a mismatch stops the build. The engine package must also carry Apple's `Developer ID Installer: Apple Inc.` signature. CI caches the same folder keyed on the hash of `deps.env`, so bumping a pin downloads the new file once.

QEMU and swtpm aren't pinned by checksum: they're whatever Homebrew bottles are installed on the build machine. `fetch-deps.sh` records the version of every formula that contributed a file in `QEMU/formulae.txt` and `ThirdParty/versions.json`, and release builds publish the matching sources.

The firmware is pinned by its recipe: Ubuntu 24.04's current `edk2` source package at build time. Its exact version is written to `Firmware/VERSION` (for example `2024.02-2ubuntu0.x + ContainerScope logo`). In CI, the firmware is cached by the hash of `Firmware/**` and `Scripts/build-firmware.sh`, so changing the recipe, the logo or the build script rebuilds it.

## Updating a component

Every update goes in the [changelog](../../CHANGELOG.md) under **Unreleased**, and [THIRD_PARTY_NOTICES.md](../../THIRD_PARTY_NOTICES.md) and the README's "What's in the app" table need the new versions.

### Apple `container` engine

1. Find the new release on [apple/container releases](https://github.com/apple/container/releases) and its `container-X.Y.Z-installer-signed.pkg`.
2. Get its checksum:
   ```sh
   curl -fLO https://github.com/apple/container/releases/download/X.Y.Z/container-X.Y.Z-installer-signed.pkg
   shasum -a 256 container-X.Y.Z-installer-signed.pkg
   ```
3. Update `CONTAINER_VERSION`, `CONTAINER_PKG_URL` and `CONTAINER_PKG_SHA256`.
4. `rm -rf build/deps/engine && Scripts/fetch-deps.sh && Scripts/build-app.sh`, then test containers, machines and Kubernetes. Check the release notes for CLI changes the bridge depends on (JSON output fields, `system start` flags, `machine` and `k8s` subcommands).

### Kernel

The kernel should match what the new engine recommends:

```sh
container system property list
```

shows `kernel.url` and `kernel.binaryPath`. Update `KATA_VERSION`, `KATA_URL`, `KATA_SHA256` (`shasum -a 256` of the archive), `KERNEL_MEMBER` (`kernel.binaryPath` without the leading `/`, resolved to the real file name in the archive) and `KERNEL_VERSION`. Then `rm -rf build/deps/kernel && Scripts/fetch-deps.sh`.

Users who already have a default kernel keep it; the bundled kernel is only installed when there's none.

### QEMU and swtpm

```sh
brew upgrade qemu swtpm
rm -rf build/deps/qemu && Scripts/fetch-deps.sh && Scripts/build-app.sh
```

Then create and boot a Windows VM, and check `ThirdParty/homebrew-formulae.txt` for libraries that were added or removed so THIRD_PARTY_NOTICES.md stays accurate.

### Firmware

Change [`Firmware/build-aavmf.sh`](../../Firmware/build-aavmf.sh) (or [`Firmware/Logo.png`](../../Firmware/Logo.png) via [`Artwork/render.sh`](../../Artwork/render.sh)), then:

```sh
rm -rf build/deps/firmware && Scripts/build-firmware.sh
```

To pick up a new Ubuntu `edk2` security update without other changes, rebuild the same way. CI won't notice an upstream update on its own because its cache key only covers `Firmware/**` and `Scripts/build-firmware.sh`; make a change under `Firmware/` (for example a comment in `build-aavmf.sh` naming the new version) to force a rebuild. The app compares the bundled `VERSION` with the expanded copy in `~/Library/Application Support/ContainerScope/Firmware` and replaces it on the next VM start, so existing VMs get the new firmware; each VM keeps its own `vars.fd`.

## Licence compliance

- `ThirdParty/` inside the app carries the licence texts and versions of everything bundled.
- For the GPL/LGPL components (the kernel, QEMU and the LGPL Homebrew libraries), each release publishes `ContainerScope-X.Y.Z-third-party-sources.tar` next to the DMG, built by [`Scripts/collect-sources.sh`](../../Scripts/collect-sources.sh). It contains the Homebrew source tarball and `.rb` build recipe of every formula listed in `formulae.txt`, the Linux kernel release (`linux-6.18.35.tar.xz`) and the Kata Containers tree that configures and patches it (`kata-containers-3.32.0.tar.gz`).
- Apple's engine (Apache-2.0) and EDK2 (BSD-2-Clause-Patent) aren't in that tarball; their sources are linked from [THIRD_PARTY_NOTICES.md](../../THIRD_PARTY_NOTICES.md).
- The firmware's recipe is in this repository, and its source is Ubuntu's `edk2` package.
